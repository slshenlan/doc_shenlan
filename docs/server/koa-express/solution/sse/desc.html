SSE Server 说明（plugins/sse） ​

1. 定位 ​

基于原生 http 的 服务端推送（Server-Sent Events）封装。 挂到 Koa 同一 http.Server，默认 path /sse，浏览器用 EventSource 直连即可。

唯一使用方式：进程全局单例 sseServer + 插件生命周期。 启动走 startSsePlugin，业务能力一律从 sseServer 出发，不要再 new SseService。

与 WebSocket 的取舍：SSE 是单向的（服务端 → 客户端），走普通 HTTP，天然穿透代理、自带断线重连与 Last-Event-ID 续传。 只做「服务端推消息给前端」用 SSE 更省事；需要客户端上行请用 plugins/websocket。

2. 依赖 ​

包用途
emittery内部事件总线
node:http直接复用 Koa 的 HTTP Server

无需额外安装 SSE 相关依赖，协议帧由 utils/payload.ts 自行拼装。

3. 文件结构 ​

相关配置在 .env.*（ENV_SSE_*）；进程退出由 src/core/lifecycle 统一处理（任务里调 stopSsePlugin()）。

文件 / 目录职责
index.ts导出单例 sseServer、生命周期、类型与常量
lifecycle/startSsePlugin / stopSsePlugin
facade/SseService 门面；业务唯一入口
manager/连接编排、心跳、房间、历史重放、ClientRegistry、health
server/请求拦截器工厂（挂 HTTP）与 path 匹配
handler/Koa 风格连接中间件 + onConnect 路由
auth/连接认证
config/从 coreConfigEnv 解析配置
constants/状态、事件名、HTTP 状态、默认值
errors/领域错误
types.ts公共类型
utils/事件总线、SSE 帧编码与历史缓冲

服务链：

text
Bootstrap → Config → Server(attach) → Manager → Handler → Facade → Global
1

4. 挂载方式（与 WebSocket 的关键差异） ​

WebSocket 用 new WebSocketServer({ server }) 挂 upgrade 事件，互不干扰。 SSE 是普通 HTTP GET，没有 upgrade 阶段，所以 attachSseRequestHandler 采取的是接管 request 监听器的做法：

text
1. 取出 httpServer 现有的 request listeners（即 Koa 的 callback）并缓存
2. removeAllListeners('request')
3. 装上自己的 dispatcher：命中 path → 建立 SSE 流；未命中 → 依次调用缓存的原 listeners
1
2
3

由此带来两条硬约束：

  • 必须在 Koa 的 http.createServer(app.callback()) 之后启动，否则会把还没注册的 Koa 监听器漏掉
  • detach() 只在「当前没有任何 request listener」时才恢复原监听器，避免覆盖之后挂上去的其它拦截器

如果以后还要挂第三个类似的拦截器，建议统一改成一个 request 分发层，不要各自 removeAllListeners。

5. 能力 ​

  1. 启停：startSsePlugin / stopSsePlugin / sseServer.start / stop
  2. 推送：send / broadcast / toRoom
  3. 连接处理：onConnect / use（连接建立时执行一次，不是消息中间件）
  4. 房间：joinRoom / leaveRoom / getRoomClients / listRooms；客户端可用 query 声明
  5. 认证：setAuthenticate（连接阶段，可返回 clientId / meta / rooms）
  6. 客户端：listClients / getClient / disconnectClient
  7. 事件：on / once / off（SseServerEvent）
  8. 健康：isRunning / getState / health
  9. 心跳：定时写 : ping <ts> 注释行保活（EventSource 会自动忽略）
  10. 断线续传：Last-Event-ID 重放历史事件

日志：模块内用 logger.sseServer。

6. 配置（coreConfigEnv） ​

字段说明默认
ENV_SSE_ENABLE是否启用false
ENV_SSE_PATH挂载 path/sse
ENV_SSE_AUTH_ENABLE是否强制连接认证false
ENV_SSE_HEARTBEAT_INTERVAL心跳间隔 ms15000
ENV_SSE_RETRY下发给 EventSource 的重连间隔提示 ms3000
ENV_SSE_MAX_CONNECTIONS最大并发连接数（0 = 不限）10000
ENV_SSE_HISTORY_SIZE历史缓冲条数（0 = 关闭重放）100
ENV_SSE_SHUTDOWN_TIMEOUT优雅关闭超时 ms10000
ENV_SSE_CORS_ORIGINCORS Origin（* 或具体 origin）*

env 留空时回落到 SSE_SERVER_DEFAULTS。enable=false 时 start 直接跳过；业务再调 send 等会抛 SseServerNotEnabledError。

corsOrigin 为具体 origin 时会自动带上 Access-Control-Allow-Credentials: true（* 与 credentials 互斥，所以只在具体 origin 下开启）。

7. 帧格式与内置事件 ​

服务端下发的每一帧：

text
id: 3f1c...
event: notice
retry: 3000
data: {"tip":"hello"}
1
2
3
4
5

业务信封与 WebSocket 一致，{ event, data, id?, retry? }；传普通对象时 event 默认为 message。 多行 data 会按 SSE 规范拆成多条 data: 行。

内置 event说明
connected连接建立后立即下发，data 含 clientId / rooms / at
error服务端主动断开前下发，data.reason 为原因
ping心跳（实际以注释行 : ping <ts> 发送，前端无需处理）

8. 使用 ​

8.1 在 server.ts 中启动 + 优雅退出 ​

ts
import http from 'http';

import app from './app';
import { coreConfigEnv } from './core/config/env';
import { registerGracefulShutdown } from './core/lifecycle';
import { SseServerEvent, sseServer, startSsePlugin, stopSsePlugin } from './plugins/sse';

const server = http.createServer(app.callback());

registerGracefulShutdown({
  server,
  tasks: [
    {
      name: 'sse',
      run: () => {
        return stopSsePlugin();
      }
    }
  ]
});

server.listen(coreConfigEnv.ENV_API_SERVER_PORT, async () => {
  try {
    await startSsePlugin({ httpServer: server });

    sseServer.on(SseServerEvent.Ready, (health) => {
      logger.sseServer.info('SSE ready', health);
    });
  } catch (error) {
    logger.sseServer.error('SSE Server 启动失败', error);
  }
});

8.3 业务模块里推送 ​

ts
import { sseServer } from '../../plugins/sse';

// 推给一个人
await sseServer.send(userId, { event: 'notice', data: { tip: '已支付' } });

// 全员广播
await sseServer.broadcast({ event: 'notice', data: { tip: '系统维护' } });

// 房间推送
sseServer.joinRoom(userId, `order:${orderId}`);
await sseServer.toRoom(`order:${orderId}`, {
  event: 'order.status',
  data: { status: 'paid' }

8.4 房间三种进法 ​

方式示例
连接 query/sse?rooms=a,b 或 /sse?room=a&room=b
认证返回setAuthenticate 返回 { ok: true, rooms }
服务端sseServer.joinRoom(clientId, 'room-1')

SSE 是单向的，客户端不能像 WebSocket 那样发消息加入房间，只能靠上面三种。

8.5 认证 / 中间件（在 start 前） ​

ts
sseServer.setAuthenticate(async ({ url, headers, lastEventId }) => {
  const token = url.searchParams.get('token') || headers.authorization;
  if (!token) {
    return { ok: false, reason: 'unauthorized' };
  }
  return { ok: true, clientId: 'u-1', meta: { userId: 'u-1' }, rooms: ['notice'] };
});

sseServer.use(async (ctx, next) => {
  ctx.state.traceId = String(Date.now());
  await next();
});

sseServer.onConnect((ctx) => {
  logger.sseServer.info('新连接', { clientId: ctx.clientId, rooms: ctx.rooms });
});

await startSsePlugin({ httpServer: server });

8.6 API ​

API说明
startSsePlugin({ httpServer })启动插件
stopSsePlugin()停止插件（由统一优雅退出调用）

sseServer.joinRoom / leaveRoom房间

9. 注意 ​

  1. 只有这一份单例，不要再造 SseService（测试可用 resetSseService）。
  2. 必须传 httpServer，且要在 Koa callback 挂到 server 之后启动（见第 4 节）。
  3. ENV_SSE_ENABLE=false 时 start 静默跳过。
  4. authEnable=true 且未 setAuthenticate 会拒绝全部连接。
  5. onConnect / on 返回的 off 须在模块卸载时调用。
  6. 同 clientId 重连会踢掉旧连接；旧连接的 close 回调有做「注册表仍指向本 response」校验，不会误删新条目。
  7. SSE 单向，客户端无法上行；需要双向请用 WebSocket。
  8. Last-Event-ID 对应的事件若已滚出历史缓冲，则不重放（避免整库重推），业务侧要能容忍这段空洞。
  9. historySize 是全局缓冲，房间事件靠 rooms 字段过滤；缓冲越大内存占用越高。
  10. 浏览器对同域 SSE 连接数有限制（HTTP/1.1 下约 6 条），前端不要一个页面开多条。
  11. Nginx 反代需要关掉缓冲（代码里已下发 X-Accel-Buffering: no，仍建议在 nginx 侧配 proxy_buffering off）。
  12. SseServerTooManyConnectionsError 目前只定义未使用——manager 在超限时直接返回 429 响应体，没有抛这个错误。要统一走领域错误的话需要另行改造。
  13. 进程退出用 registerGracefulShutdown（core/lifecycle），任务里调 stopSsePlugin()；勿在插件内再叠加 SIGINT/SIGTERM 钩子。
